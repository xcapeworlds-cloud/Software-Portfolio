01 / Featured technical case study · Unity / C#

Sugar.io — separating gameplay responsibilities

A tornado arena prototype with movement, AI opponents, collectible objects, growth, and collision rules.

The problem: As gameplay features grew, keeping logic organized became harder. I worked on separating responsibilities into focused scripts and methods so the code was easier to follow and change.

My role: Gameplay direction, project structure, reviewing and organizing implementation. I used AI assistance for parts of the code and worked to understand and improve the results. The showcase changes are not claimed to be compiled or play tested in the original Unity project.

Technical approach: The showcase organizes gameplay behaviors into separate C# scripts for player movement, AI behavior, collectibles, and game state. The repository includes architecture notes explaining the responsibilities and tradeoffs.

Verification: Source and documentation are public. Changes made for the code showcase were not compiled or play tested in the original Unity project.
